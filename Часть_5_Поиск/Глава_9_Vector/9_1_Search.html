Chapter 9.1

9.1 Vector search основы

В основе эффективной работы систем RAG (Retrieval Augmented Generation) лежит способность быстро и точно находить релевантную информацию в огромных массивах данных. Именно здесь в игру вступает векторный поиск – технология, которая трансформирует текстовые и другие данные в числовые векторы (эмбеддинги) и позволяет искать их по семантическому сходству, а не только по ключевым словам. Понимание принципов векторного поиска критически важно для любого, кто разрабатывает или оптимизирует RAG-системы.

Как работает векторный поиск: от эмбеддингов до метрик сходства

Центральным элементом векторного поиска являются **эмбеддинги (embeddings)**. Это плотные числовые представления (векторы) текста, изображений, аудио или других типов данных, сгенерированные моделями машинного обучения (часто LLM или специализированными моделями, такими как `sentence-transformers`). Ключевое свойство эмбеддингов заключается в том, что семантически похожие элементы располагаются близко друг к другу в многомерном векторном пространстве. Например, если вы сгенерируете эмбеддинги для предложений "Кот сидит на коврике" и "Кошка лежит на циновке", их векторы будут находиться гораздо ближе друг к другу, чем векторы для "Космический корабль летит на Марс", даже если в последнем тоже есть слово "корабль", но в другом контексте. Процесс векторного поиска состоит из нескольких шагов: 1. **Векторизация**: Все документы в вашей базе знаний (корпусе) преобразуются в эмбеддинги с помощью выбранной модели. Эти векторы затем индексируются и сохраняются в специализированной векторной базе данных. 2. **Запрос**: Когда пользователь задает вопрос, этот вопрос также преобразуется в эмбеддинг с использованием той же модели. 3. **Поиск сходства**: Вектор запроса сравнивается со всеми векторами в базе данных для определения наиболее похожих. Для определения "похожести" используются различные **метрики сходства (similarity metrics)**: * **Косинусное сходство (Cosine Similarity)**: Наиболее распространенная метрика. Она измеряет косинус угла между двумя векторами. Чем ближе значение к 1, тем более похожи векторы (и, следовательно, их исходное содержимое). Это хороший выбор, когда важна направленность векторов, а не их абсолютная длина. * **Евклидово расстояние (Euclidean Distance)**: Измеряет "прямое" расстояние между двумя точками в многомерном пространстве. Меньшее расстояние указывает на большее сходство. Часто используется, когда длина вектора имеет значение. * **Скалярное произведение (Dot Product)**: Похоже на косинусное сходство, но также учитывает величину векторов. Если векторы нормализованы (имеют единичную длину), скалярное произведение эквивалентно косинусному сходству. Выбор метрики может зависеть от используемой модели эмбеддингов и конкретной задачи. Многие модели, такие как те, что из библиотеки `sentence-transformers`, оптимизированы для косинусного сходства. 

from sentence_transformers import SentenceTransformer
from sklearn.metrics.pairwise import cosine_similarity
import numpy as np

# 1. Загрузка модели эмбеддингов
model = SentenceTransformer('all-MiniLM-L6-v2')

# 2. Создание текстовых данных
sentences = [
    "Кошка сидит на коврике.",
    "Кот лежит на циновке.",
    "Собака лает на луну.",
    "Космический корабль летит к звездам."
]

# 3. Генерация эмбеддингов для каждого предложения
embeddings = model.encode(sentences)

# 4. Выбор запроса
query_sentence = "Маленький котенок спит на подушке."
query_embedding = model.encode([query_sentence])

# 5. Вычисление косинусного сходства между запросом и всеми предложениями
similarities = cosine_similarity(query_embedding, embeddings)

# 6. Вывод результатов
print(f"Запрос: '{query_sentence}'\n")
for i, sentence in enumerate(sentences):
    print(f"Предложение: '{sentence}' | Сходство: {similarities[0][i]:.4f}")

# Ожидаемый вывод (значения могут незначительно отличаться):
# Запрос: 'Маленький котенок спит на подушке.'
#
# Предложение: 'Кошка сидит на коврике.' | Сходство: 0.65xx
# Предложение: 'Кот лежит на циновке.' | Сходство: 0.62xx
# Предложение: 'Собака лает на луну.' | Сходство: 0.20xx
# Предложение: 'Космический корабль летит к звездам.' | Сходство: 0.05xx

Качество эмбеддингов — это фундамент эффективного RAG. Даже самый быстрый векторный поиск не поможет, если ваши векторы не точно отражают семантику информации. Инвестируйте в выбор и, при необходимости, дообучение модели эмбеддингов, чтобы она максимально соответствовала домену ваших данных.

Типы векторного поиска: от точного до приближенного

Когда речь идет о поиске ближайших соседей (nearest neighbors) в векторном пространстве, существуют два основных подхода:

Brute-Force (Точный поиск ближайших соседей - ENN)

Этот метод, также известный как Exact Nearest Neighbor (ENN), является самым простым и точным. Он предполагает вычисление метрики сходства между вектором запроса и *каждым* вектором в базе данных. * **Преимущества**: Гарантирует нахождение *истинно* ближайших соседей. * **Недостатки**: Чрезвычайно медленный для больших наборов данных. Его вычислительная сложность растет линейно с количеством векторов (O(N*D), где N — количество векторов, D — размерность). Для миллионов или миллиардов векторов такой подход неприемлем. * **Применение**: Используется для небольших наборов данных или для бенчмаркинга производительности других, более сложных методов.

Approximate Nearest Neighbor (Приближенный поиск ближайших соседей - ANN)

Большинство реальных систем RAG используют методы Approximate Nearest Neighbor (ANN). Эти методы жертвуют небольшой долей точности в пользу значительного увеличения скорости поиска. Вместо того чтобы просматривать каждый вектор, ANN-алгоритмы используют различные структуры данных и индексы для быстрого сужения области поиска. Наиболее популярные алгоритмы ANN включают: * **Hierarchical Navigable Small Worlds (HNSW)**: Один из самых эффективных и широко используемых алгоритмов. Он строит многослойный граф, где нижние слои содержат более мелкие связи для точного поиска, а верхние слои — более длинные связи для быстрого перемещения по пространству.
