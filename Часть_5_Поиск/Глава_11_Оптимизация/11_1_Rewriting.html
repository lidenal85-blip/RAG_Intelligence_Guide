11.1 Query rewriting

Переписывание запросов (Query rewriting) — это критически важный этап в архитектуре систем генерации с дополненным поиском (RAG), цель которого — трансформировать исходный запрос пользователя в форму, более подходящую для эффективного извлечения релевантной информации из векторных баз данных. Пользовательские запросы часто бывают неоднозначными, слишком короткими, чрезмерно длинными, содержат разговорные выражения или подразумевают контекст, который неявно понятен человеку, но не оптимален для поиска по семантическим встраиваниям. Задача переписывания запроса заключается в устранении этого разрыва, повышая вероятность того, что система извлечет наиболее точные и полезные документы.

"Качество извлеченных документов напрямую зависит от качества запроса. Переписывание запросов — это не просто улучшение формулировки, это стратегическое преобразование намерения пользователя в сигнал, который может быть эффективно обработан векторной базой данных, будь то Qdrant, Weaviate или Pinecone."

Зачем переписывание запросов критически важно для RAG?

В основе любой RAG-системы лежит механизм извлечения (retrieval), который обычно полагается на векторные встраивания (embeddings). Когда пользователь вводит запрос, он преобразуется в вектор, который затем используется для поиска ближайших векторов в базе данных документов. Если исходный запрос пользователя нечеткий, слишком общий или имеет плохую формулировку, полученный вектор может плохо отражать истинное намерение пользователя. Это приводит к извлечению нерелевантных или менее полезных документов, что, в свою очередь, негативно сказывается на качестве окончательного ответа, генерируемого большой языковой моделью (LLM). Переписывание запросов помогает решить несколько ключевых проблем: 1. **Неоднозначность и неполнота:** Пользователи часто задают короткие или неполные вопросы, особенно в начале диалога. LLM может обогатить запрос, добавив необходимый контекст или уточнив его. 2. **Разговорный язык:** Запросы могут быть сформулированы в разговорном стиле, что не всегда оптимально для поиска по ключевым словам или семантического поиска, обученного на более формальных текстах. Переписывание может перевести запрос в более "поисковую" форму. 3. **Сложные запросы:** Один запрос может содержать несколько подвопросов или требовать информации из разных областей. Переписывание может разбить такой запрос на несколько более простых. 4. **Сдвиг в распределении данных (Distribution Shift):** Встраивания запросов могут отличаться по распределению от встраиваний документов, на которых обучалась модель. Переписывание, особенно такие методы, как HyDE, помогают сблизить эти распределения. 5. **Повышение точности (Recall) и релевантности (Precision):** Генерируя несколько вариантов запроса или более сфокусированные запросы, мы увеличиваем шансы найти все релевантные фрагменты информации.

Основные стратегии и методы переписывания запросов

Существует несколько эффективных стратегий переписывания запросов, каждая из которых имеет свои преимущества и области применения: 1. **Простое перефразирование/расширение (Simple Rephrasing/Expansion):** * **Метод:** Использование LLM для генерации нескольких альтернативных формулировок исходного запроса или его расширения дополнительными ключевыми словами/контекстом. * **Пример:** Исходный запрос: "RAG". Перефразированный: "Что такое RAG-система?", "Как работают системы генерации с дополненным поиском?". * **Инструменты:** LangChain, LlamaIndex с использованием OpenAI GPT-3.5/4, Anthropic Claude или других LLM. 2. **Декомпозиция запроса (Query Decomposition):** * **Метод:** Разделение сложного, многоаспектного запроса на несколько более простых, атомарных подзапросов. Каждый подзапрос обрабатывается отдельно, а результаты объединяются. * **Пример:** Исходный запрос: "Какие бывают типы векторных баз данных и чем Qdrant отличается от Weaviate?". Декомпозиция: 1) "Типы векторных баз данных", 2) "Отличия Qdrant от Weaviate". * **Преимущества:** Эффективно для очень сложных запросов, когда один поиск не может охватить все аспекты. 3. **Гипотетическое встраивание документа (Hypothetical Document Embedding, HyDE):** * **Метод:** LLM генерирует гипотетический, но релевантный документ-ответ на основе исходного запроса. Затем этот *гипотетический документ* встраивается в вектор, и этот вектор используется для поиска в базе данных. * **Причина эффективности:** Вектор гипотетического документа часто семантически ближе к реальным документам в базе данных, чем вектор самого запроса, что улучшает качество поиска. * **Инструменты:** LangChain (например, `HypotheticalDocumentEmbedder`), LlamaIndex. 4. **Генерация нескольких запросов (Multi-query Generation / RAG-Fusion):** * **Метод:** LLM генерирует несколько разнообразных запросов, которые все отражают исходное намерение пользователя. Затем каждый из этих запросов используется для независимого поиска в векторной базе данных. Полученные результаты объединяются и переранжируются (например, с использованием Reciprocal Rank Fusion, RRF). * **Преимущества:** Значительно повышает полноту (recall), поскольку разные формулировки могут "поймать" разные релевантные документы. * **Инструменты:** LangChain, LlamaIndex. 5. **Контекстуализация запроса (Contextualization):** * **Метод:** В диалоговых системах, когда пользователь задает последующий вопрос, LLM может использовать историю беседы для обогащения или переформулирования текущего запроса, чтобы он был самодостаточным. * **Пример:** Пользователь 1: "Какие основные преимущества Qdrant?". Пользователь 2: "А как насчет Weaviate?". Контекстуализированный запрос: "Какие основные преимущества Weaviate по сравнению с Qdrant?".

Pro-Tip: При внедрении переписывания запросов всегда используйте A/B-тестирование. Различные стратегии могут работать по-разному в зависимости от домена данных и профиля пользовательских запросов. Экспериментируйте с промптами для LLM, чтобы тонко настроить поведение переписывания, например, запрашивать более агрессивное перефразирование или более сфокусированную декомпозицию.
