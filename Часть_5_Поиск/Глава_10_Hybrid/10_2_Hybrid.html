10.2 Hybrid search стратегии

Гибридный поиск представляет собой мощную стратегию для Retrieval-Augmented Generation (RAG) систем, объединяющую несколько методов поиска для получения наиболее релевантных документов. В то время как чисто семантический поиск (на основе векторных эмбеддингов) отлично справляется с пониманием смысла запроса и поиском синонимов, он может испытывать трудности с точным соответствием конкретным ключевым словам, редким терминам или числовым идентификаторам. С другой стороны, традиционный поиск по ключевым словам (например, BM25 или TF-IDF) превосходно находит точные совпадения, но не учитывает семантический контекст. Гибридный поиск направлен на преодоление этих ограничений, используя сильные стороны каждого подхода для повышения как полноты (recall), так и точности (precision) извлекаемых данных.

Основы гибридного поиска: объединение сильных сторон

В основе гибридного поиска лежит идея, что ни один метод поиска не является идеальным для всех типов запросов и всех наборов данных. Объединяя различные подходы, мы можем создать более устойчивую и эффективную систему RAG. Наиболее распространенная комбинация включает: 1. **Семантический поиск (Dense Vector Search):** Использует модели эмбеддингов (например, Sentence Transformers, OpenAI embeddings) для преобразования запроса и документов в векторные представления. Поиск осуществляется путем нахождения векторов документов, наиболее близких к вектору запроса в многомерном пространстве. Этот метод отлично подходит для запросов, требующих понимания контекста и смысла, например, "каковы основные принципы квантовой механики?". 2. **Поиск по ключевым словам (Sparse Vector Search / Lexical Search):** Основан на статистическом анализе слов, таких как BM25 (Best Match 25) или TF-IDF (Term Frequency-Inverse Document Frequency). Эти алгоритмы оценивают релевантность документа на основе частоты вхождения терминов запроса и их редкости в общей коллекции. Идеален для запросов, содержащих специфические имена, даты, коды или точные формулировки, например, "дата релиза Python 3.12". Гибридный поиск не ограничивается только этими двумя методами. Он может также включать: * **Поиск по метаданным:** Фильтрация документов на основе структурированных данных, таких как автор, дата публикации, тип документа. * **Поиск по графу знаний:** Использование графовых баз данных для извлечения сущностей и отношений, что особенно полезно для фактологических запросов. Цель состоит в том, чтобы запустить несколько независимых запросов, собрать результаты от каждого из них, а затем объединить и переранжировать эти результаты, чтобы представить пользователю наиболее релевантный набор документов.

Методы объединения и переранжирования результатов

После выполнения нескольких типов поиска возникает задача эффективного объединения и упорядочивания полученных списков документов. Различные методы имеют свои преимущества и недостатки: 1. **Reciprocal Rank Fusion (RRF):** Это один из наиболее популярных и эффективных методов, поскольку он не требует нормализации оценок релевантности между различными поисковыми системами. RRF работает следующим образом: * Для каждого документа в каждом списке результатов вычисляется балл RRF по формуле: `RRF_score = Σ (1 / (rank_i + k))`, где `rank_i` — ранг документа в i-м списке результатов, а `k` — константа (обычно 60), которая уменьшает влияние очень высоких рангов. * Документы с более высокими баллами RRF считаются более релевантными. Преимущество RRF заключается в его простоте и надежности; он хорошо работает даже тогда, когда различные поисковые системы выдают результаты с сильно отличающимися диапазонами оценок. 2. **Взвешенная сумма (Weighted Sum):** В этом подходе каждая поисковая система выдает оценку релевантности, и эти оценки суммируются с определенными весами: `Final_score = w1 * score1 + w2 * score2 + ...`. Главная сложность здесь заключается в необходимости нормализации оценок от разных систем (например, масштабирование до диапазона [0,1]) и подборе оптимальных весов `w_i`. Неправильная нормализация или веса могут привести к доминированию одного типа поиска. 3. **Последовательная фильтрация/переранжирование:** В этом подходе один метод поиска используется для создания начального набора кандидатов, а затем другой, более "дорогой" или точный метод, применяется для переранжирования этих кандидатов. Например, быстрый поиск по ключевым словам может выбрать 1000 потенциальных документов, а затем семантический поиск или кросс-энкодер переранжирует только эти 1000, чтобы найти топ-K. 4. **Кросс-энкодеры (Cross-encoders):** После того как гибридный поиск выдал начальный список релевантных документов, часто применяется дополнительный шаг переранжирования с использованием кросс-энкодеров (например, на основе архитектуры BERT). Кросс-энкодеры принимают пару (запрос, документ) и выдают одну оценку релевантности. Они значительно точнее, чем би-энкодеры (используемые для семантического поиска), но гораздо медленнее, поэтому их обычно применяют только к небольшому количеству (например, 20-50) наиболее релевантных документов, полученных на предыдущем этапе.
"Эффективность гибридного поиска не в том, чтобы заменить один метод другим, а в том, чтобы создать синергию, где каждый компонент покрывает недостатки других. Это искусство балансирования между точностью и полнотой, адаптированное под динамику запроса."

Реализация гибридного поиска на практике

Реализация гибридного поиска требует интеграции различных компонентов и часто использования специализированных инструментов. **1. Векторные базы данных (Vector Databases):** Многие современные векторные базы данных предлагают встроенную поддержку гибридного поиска или легко интегрируются с ним: * **Qdrant:** Поддерживает индексирование и поиск как по плотным (dense) векторам, так и по разреженным (sparse) векторам (например, для BM25). Это позволяет выполнять гибридный поиск на стороне базы данных, что значительно повышает производительность. В Qdrant можно комбинировать `vector` (для плотных векторов) и `sparse_vector` (для разреженных) запросы, а затем использовать различные стратегии объединения результатов. * **Weaviate:** Также предлагает нативную поддержку гибридного поиска, позволяя объединять векторный поиск с поиском по BM25 или TF-IDF. * **Pinecone:** Предоставляет функциональность для комбинирования различных типов поиска, хотя часто это требует более ручной оркестрации. **2. Фреймворки для RAG:** Такие фреймворки, как LangChain и LlamaIndex, предоставляют абстракции для упрощения реализации гибридного поиска: * **LangChain:** Имеет компонент `EnsembleRetriever`, который позволяет объединять результаты от нескольких `Retriever` объектов (например, `BM25Retriever` и `VectorStoreRetriever`) с использованием RRF.
