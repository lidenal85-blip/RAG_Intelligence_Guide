14.1 Вставка контекста в промпт

В архитектуре RAG (Retrieval-Augmented Generation) этап вставки контекста в промпт является критически важным мостом между извлеченной информацией и генерацией ответа большой языковой моделью (LLM). Без эффективной вставки контекста даже самые релевантные документы, найденные на этапе извлечения, не смогут быть использованы LLM должным образом, что приведет к неточным, галлюцинаторным или неполным ответам. Этот раздел посвящен методам, стратегиям и лучшим практикам для оптимальной интеграции контекста в промпт, максимизируя полезность LLM.

Основная цель вставки контекста — предоставить LLM всю необходимую информацию для ответа на запрос пользователя, минимизируя при этом ее склонность к "галлюцинациям" и обеспечивая фактологическую точность. Контекст, как правило, состоит из одного или нескольких текстовых фрагментов (чанков), извлеченных из базы знаний (например, из векторной базы данных, такой как Qdrant, Weaviate или Pinecone), которые алгоритм извлечения счел наиболее релевантными запросу пользователя.

Основы и механика вставки контекста

Механически, вставка контекста сводится к конкатенации (объединению) извлеченных текстовых фрагментов с запросом пользователя и, возможно, с системными инструкциями, формируя единый промпт, который затем отправляется LLM. Однако дьявол кроется в деталях: как именно эта конкатенация выполняется, как структурируется контекст и какие инструкции даются LLM, значительно влияет на качество конечного ответа.

Типичная структура промпта с внедренным контекстом выглядит следующим образом:

  1. **Системные инструкции (System Prompt):** Общие указания для LLM о ее роли, стиле ответа, ограничениях и т.д. Например: "Ты — эксперт по документации компании. Отвечай на вопросы, используя только предоставленный контекст."
  2. **Вставленный контекст (Context):** Один или несколько извлеченных документов или их фрагментов. Это может быть простой список или более сложная структурированная форма с указанием источников.
  3. **Запрос пользователя (User Query):** Сам вопрос или задача, которую пользователь задает LLM.
  4. **Инструкции по использованию контекста (Contextual Instructions):** Иногда эти инструкции встраиваются прямо перед или после контекста, явно указывая LLM, как работать с предоставленной информацией. Например: "Используй следующие документы для ответа:" или "Если ответ не найден в контексте, сообщи об этом."

Эффективная вставка контекста требует не только добавления текста, но и его форматирования таким образом, чтобы LLM могла легко его идентифицировать, обрабатывать и использовать. Использование четких разделителей и метаданных (например, название документа, номер страницы, URL) может значительно улучшить интерпретацию контекста моделью.

Методы и стратегии форматирования контекста

Существует несколько подходов к форматированию и вставке контекста, каждый из которых имеет свои преимущества и недостатки:

1. Простая конкатенация с разделителями

Самый базовый метод, при котором извлеченные фрагменты текста просто объединяются в одну строку, разделенные четкими маркерами. Это может быть полезно для коротких, хорошо структурированных фрагментов.

Системный промпт: Ответь на вопрос, используя только предоставленную информацию.
---
Контекст:
[Документ 1]
Текст первого документа.
[Документ 2]
Текст второго документа.
---
Вопрос: [Запрос пользователя]

Преимущество: Простота реализации. Недостаток: LLM может быть сложнее различить границы отдельных документов, особенно если они длинные и без дополнительных метаданных.

2. Использование шаблонизаторов (Templating Engines)

Для более сложной и гибкой вставки контекста часто применяются шаблонизаторы. В Python это могут быть f-строки или более мощные инструменты, такие как `PromptTemplate` из LangChain или Jinja2. Они позволяют динамически вставлять переменные (системные инструкции, контекст, запрос пользователя) в предопределенный шаблон промпта.


from langchain_core.prompts import PromptTemplate

# Предположим, что мы извлекли два документа
retrieved_docs = [
    {"source": "Документ А", "content": "RAG (Retrieval-Augmented Generation) — это архитектура ИИ, которая сочетает в себе извлечение информации и генерацию текста LLM."},
    {"source": "Документ Б", "content": "Qdrant — это высокопроизводительная векторная база данных с открытым исходным кодом, предназначенная для хранения и поиска векторов с метаданными."}
]

# Форматируем каждый документ для вставки
formatted_context = "\n\n".join([
    f"Источник: {doc['source']}\nТекст: {doc['content']}"
    for doc in retrieved_docs
])

# Определяем шаблон промпта
prompt_template = PromptTemplate.from_template(
    """Ты — эксперт по технологиям RAG и векторным базам данных. Ответь на вопрос пользователя, основываясь исключительно на предоставленном контексте.
Если ответ не может быть найден в контексте, честно сообщи об этом.

---
Контекст:
{context}
---

Вопрос пользователя: {query}

Ответ:"""
)

user_query = "Что такое RAG и какая векторная база данных упомянута в контексте?"

# Создаем финальный промпт
final_prompt = prompt_template.format(context=formatted_context, query=user_query)

print(final_prompt)

# Пример вывода:
# Ты — эксперт по технологиям RAG и векторным базам данных. Ответь на вопрос пользователя, основываясь исключительно на предоставленном контексте.
# Если ответ не может быть найден в контексте, честно сообщи об этом.
#

# Контекст:

3. Управление окном контекста (Context Window Management)

Одно из ключевых ограничений LLM — это максимальный размер входного промпта, известный как "окно контекста". Модели, такие как GPT-3.5 Turbo (16k токенов), GPT-4 Turbo (128k токенов) или Claude 3 Opus (200k токенов), имеют лимиты. Если сумма токенов системного промпта, извлеченного контекста и запроса пользователя превышает этот лимит, промпт будет обрезан или вызовет ошибку.

Стратегии для управления окном контекста:

  • **Усечение (Truncation):** Простейший метод — обрезать контекст до максимально допустимого размера. Это может привести к потере важной информации.
  • **Суммаризация (Summarization):** Вместо усечения, можно суммаризировать извлеченные документы (или их часть) перед вставкой в промпт. Это требует дополнительного вызова LLM для суммаризации, но может сохранить суть информации.
  • **Переранжирование (Re-ranking):** После первоначального извлечения большого количества документов, можно использовать модель переранжирования (например, Cohere Rerank, BGE-Reranker) для выбора наиболее релевантных, которые поместятся в окно контекста.
