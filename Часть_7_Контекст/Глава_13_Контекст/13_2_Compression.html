13.2 Context compression

Контекстное сжатие является критически важным компонентом в современных системах Retrieval-Augmented Generation (RAG), направленным на оптимизацию объема и качества информации, передаваемой большой языковой модели (LLM). Основная цель — уместить наиболее релевантные данные в ограниченное контекстное окно LLM, одновременно снижая затраты на токены и повышая точность ответов за счет уменьшения информационного шума. Традиционные RAG-системы часто извлекают фиксированное количество "сырых" фрагментов (часто 5-10) из векторной базы данных, основываясь на векторном сходстве. Однако не все из этих фрагментов могут быть одинаково релевантными или содержать наиболее важную информацию для конкретного запроса. Более того, даже релевантные фрагменты могут содержать избыточные или второстепенные детали. Без эффективного сжатия LLM может быть перегружена неактуальной информацией, что приводит к увеличению задержки, повышению стоимости и, что более важно, к потенциальным "галлюцинациям" или менее точным ответам из-за отвлечения на шум.

Методы сжатия контекста

Сжатие контекста можно условно разделить на две основные категории: сжатие на основе извлечения (extraction-based) и сжатие на основе генерации (generation-based), а также их гибридные комбинации.

Сжатие на основе извлечения

Эти методы фокусируются на выборе наиболее релевантных частей исходного текста или переупорядочивании их без существенного изменения содержания. * **Фильтрация и переранжирование (Relevance Filtering and Re-ranking)**: * **Принцип**: После первоначального извлечения N фрагментов из векторной базы данных, эти фрагменты оцениваются на предмет их релевантности запросу с помощью более мощной модели. Модели-переранжировщики (re-rankers), такие как кросс-энкодеры (например, `sentence-transformers/msmarco-MiniLM-L-12-v2` или `cross-encoder/ms-marco-MiniLM-L-6-v2`) или коммерческие API (например, Cohere Rerank, BGE-reranker-base), принимают на вход запрос и каждый фрагмент по отдельности (или пары запрос-фрагмент) и выдают оценку релевантности. Затем выбираются K наиболее релевантных фрагментов (где K < N). * **Преимущества**: Высокая точность, сохранение оригинального текста, относительно низкий риск галлюцинаций. * **Недостатки**: Может быть вычислительно дороже, чем простое извлечение, если используется сложный переранжировщик. * **Стратегии "скользящего окна" (Sliding Window Strategies)**: * **Принцип**: Особенно полезно для обработки длинных документов или ведения диалогов. Вместо передачи всего документа, в контекст включается центральный "фокусный" фрагмент и несколько фрагментов до и после него. Это позволяет LLM видеть локальный контекст без перегрузки. В диалогах может использоваться для включения нескольких последних реплик пользователя и ассистента. * **Преимущества**: Сохраняет локальную связность, прост в реализации. * **Недостатки**: Может пропустить важную информацию, расположенную далеко от "окна". * **Извлечение ключевых предложений/абзацев (Key Sentence/Paragraph Extraction)**: * **Принцип**: Используются методы NLP (например, TextRank, LexRank) или небольшие LLM для идентификации и извлечения наиболее информативных предложений или абзацев из каждого извлеченного фрагмента. * **Преимущества**: Уменьшает объем текста, сохраняя ключевые идеи. * **Недостатки**: Может потерять нюансы или контекст, если извлечение недостаточно точное.

Сжатие на основе генерации

Эти методы используют LLM для создания нового, более краткого представления исходной информации. * **Абстрактивное суммаризация (Abstractive Summarization)**: * **Принцип**: Используется меньшая LLM (например, T5, BART) или даже основная LLM с соответствующим промтом для создания краткого, связного резюме одного или нескольких извлеченных фрагментов. Резюме может содержать информацию, которая не была явно указана в исходном тексте, но логически вытекает из него. * **Преимущества**: Значительное сокращение объема контекста, создание более связного текста. * **Недостатки**: Высокий риск галлюцинаций (модель может "придумать" факты), вычислительно затратно, требует тщательной настройки промтов. * **Извлечение фактов/сущностей (Fact/Entity Extraction)**: * **Принцип**: LLM инструктируется извлекать только конкретные факты, сущности, даты, числа или отношения из текста в структурированном формате (например, JSON). * **Преимущества**: Очень компактный контекст, удобство для машинной обработки. * **Недостатки**: Потеря повествовательного контекста, сложность промтов для обеспечения точности и полноты.

Гибридные подходы

Комбинация методов часто дает наилучшие результаты. Например, сначала переранжирование для выбора наиболее релевантных фрагментов, а затем суммаризация этих фрагментов для дальнейшего сокращения.

Инструменты и реализации

Современные RAG-фреймворки предлагают обширную поддержку для реализации различных стратегий сжатия контекста. * **LangChain**: * **`ContextualCompressionRetriever`**: Это основной класс в LangChain для реализации сжатия. Он оборачивает базовый ретривер и применяет трансформации к извлеченным документам. * **`LLMChainExtractor`**: Использует LLM для извлечения релевантных предложений из каждого документа. * **`LLMChainFilter`**: Использует LLM для фильтрации документов, оставляя только те, которые LLM считает релевантными. * **`CohereRerank`**: Интеграция с API Cohere для переранжирования документов. Также можно использовать локальные кросс-энкодеры через `HuggingFaceBgeRerank`. * **`LongContextReorder`**: Для переупорядочивания документов, помещая наиболее релевантные в начало и конец контекстного окна, где LLM, как правило, лучше их обрабатывает (так называемый "эффект середины контекста"). * **LlamaIndex**: * **`SentenceWindowNodeParser`**: Разделяет документы на предложения, но при извлечении возвращает "окно" предложений вокруг релевантного предложения, что помогает сохранить локальный контекст. * **`LLMRerank`**: Аналогично CohereRerank, но может использовать любую LLM для оценки релевантности. * **`CompactAndRefine`**: Стратегия для суммаризации, где запросы к LLM строятся таким образом, чтобы постепенно уточнять ответ, используя все извлеченные фрагменты. * **`QueryFusion`**: Генерирует несколько вариаций пользовательского запроса,
