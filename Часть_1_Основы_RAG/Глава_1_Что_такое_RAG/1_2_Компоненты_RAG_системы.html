1.2 Компоненты RAG системы

Любая RAG-система состоит из трёх макрокомпонентов, которые работают в едином пайплайне. Рассмотрим каждый детально.

📥 1. Ingestion pipeline

Подготовка данных: загрузка, очистка, chunking, генерация эмбеддингов, запись в векторную БД.

🔍 2. Retriever

Поисковый модуль: принимает запрос, превращает в вектор, ищет ближайшие чанки в векторной БД.

🧠 3. Generator (LLM)

Генеративная модель, которая получает контекст (найденные чанки) + запрос и формирует ответ.

1. Ingestion pipeline (индексация)

Этот компонент работает оффлайн или инкрементально. Задача — превратить сырые документы в структуру, пригодную для поиска.

  • Загрузчик (Loader): извлекает текст из PDF, Word, HTML, базы данных, API.
  • Парсер и очиститель: удаляет мусор, нормализует пробелы, приводит к единому регистру (опционально).
  • Сплиттер (Chunker): разбивает длинные документы на перекрывающиеся фрагменты (чанки).
  • Embedder: отправляет чанки в embedding-модель, получает векторы.
  • Векторное хранилище: сохраняет пары (вектор, метаданные, оригинальный текст).
# Пример индексации с использованием Qdrant (Python) from qdrant_client import QdrantClient from sentence_transformers import SentenceTransformer client = QdrantClient(path="./qdrant_db") encoder = SentenceTransformer('all-MiniLM-L6-v2') # Создаём коллекцию client.create_collection( collection_name="my_docs", vectors_config={"size": 384, "distance": "Cosine"} ) # Индексируем чанки for chunk in chunks: vector = encoder.encode(chunk.text).tolist() client.upsert( collection_name="my_docs", points=[{ "id": chunk.id, "vector": vector, "payload": {"text": chunk.text, "source": chunk.source} }] )

2. Retriever (поисковик)

Работает онлайн на каждый запрос пользователя. От качества поиска зависит >80% успеха RAG.

  • Query encoder: превращает запрос пользователя в вектор той же размерности, что и чанки.
  • Поисковый движок: выполняет ANN-поиск (приближённый поиск ближайших соседей) с помощью индексов HNSW, IVF или PQ.
  • Фильтрация: отсев по метаданным (дата, автор, тип документа).
  • Reranker (опционально): уточняет релевантность с помощью cross-encoder.
⚡
Лайфхак: не берите слишком много чанков (top_k). Для большинства задач 5–10 чанков оптимально. Больше → деградация качества из-за размывания контекста и превышения token budget.

3. Generator (LLM)

Генерирует ответ, используя промпт, в который вставлены извлечённые чанки и исходный запрос.

  • Промпт-шаблон: определяет, как именно вставлять контекст и запрос.
  • LLM: может быть API (OpenAI, Anthropic) или локальной (Llama, Mistral, Qwen).
  • Пост-обработка: извлечение цитат, проверка галлюцинаций, форматирование.

Если ответа нет в контексте, скажи "У меня нет информации об этом". 2. В конце ответа укажи источники в формате [1], [2]. Ответ: """
«Компоненты RAG связаны архитектурой данных. Самый слабый компонент определяет качество всей системы. Чаще всего bottleneck — это retrieval, а не генерация».

Дополнительные компоненты production‑системы

  • Кэш эмбеддингов: снижает нагрузку на embedding-модель для частых запросов.
  • Guardrails: проверяют входящие запросы и исходящие ответы на безопасность.
  • Мониторинг: логирует retrieval-результаты, latency, faithfulness.
  • Очереди запросов: обеспечивают асинхронную обработку при пиковых нагрузках.

Источники: документация Qdrant, LangChain, практика OpenAI.
